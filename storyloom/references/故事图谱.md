# 故事图谱（`故事图谱.json`）

每部剧的文件夹里放一份 `故事图谱.json`。**案子真相、真实时间线、线索表以它为准**；剧本.md 只放观众看得到的正文。

这么分的原因：
- 两处手写，迟早对不上。
- 剧本里不放真相，盲测时可以把剧本直接交出去，不会泄底。

画布（Kapi 的“剧集”，设计说明在 `/Users/liudongdong/Desktop/Projects/kapi/docs/STORY-CANVAS.md`）只读这个文件，改完点“重新读取”就能看到。检查脚本也读它：`uv run ~/.claude/skills/storyloom/scripts/check_graph.py <剧的文件夹>`。

## 谁改、什么时候改
- 谁改了剧本，谁当场同步图谱，然后跑一遍检查脚本。
- **段号要和剧本一致**。中途插段、删段，要把所有 `ep`、`seg`（节拍、线索、事件）一起改。这里最容易出错，脚本会对照剧本查。
- 这一轮改过的条目加 `"mark": "改"` 或 `"新增"`，和剧本里的【改】【新增】对应。下一轮动手之前先清掉上一轮的标记。
- 每集的 `status`：`草稿`（还在写）→ `待查`（等找茬和盲测）→ `定稿`（导演点头）。定稿的集交给 manju 拍。

## 格式
id 用小写英文、数字和下划线。没标“必填”的字段都可以不写。

```jsonc
  "title": "海声民宿",                   // 必填
  "titleKo": "바다소리 민박",
  "logline": "一句话梗概",
  "setting": "现在 · 韩国江原道海边小镇雾津",

  "note": "给导演看的一行提示",

    "id": "r302",                       // 必填
    "name": "302 · 在修",                 // 必填
    "map": "minbak", "layer": "f3",
    "rect": [3, 1, 3, 2],               // x, y, 宽, 高（网格单位）

    "spoiler": true                     // 观众此刻不知道的事（凶手偷偷做的事等）

```

## 填的时候注意
- **真实时间线写全**：凶手和每个相关的人，从案子开始到揭晓，几点在哪、干什么，都要写成事件，包括没上屏的（标 `spoiler`）。一个人在一个时刻只能在一个地方。
- **一分钟里的先后写到秒**：`at`、`until` 平时写到分钟（`D2 02:00`）。一段连续戏挤在一分钟里（比如 45 秒里新娘换了三个地方），就带上秒（`D2 02:00:43`），每一步几点几秒才分得清。不写秒就是 :00。带了秒，检查“走路够不够时间”也按秒算。
- **同一时刻的几件事，按列表顺序算先后**：同一个人的几件事 `at` 完全一样，就按它们在 `events` 里的先后，一件接一件发生：后一件开始，前一件就结束了（排在前面的只算一个瞬间，不占时间），所以不算“同时在两个地方”。没写 `until` 的事件，到他下一件事开始为止，最长 15 分钟；写了 `until` 的，以 `until` 为准。只有两段时间真的重叠，或者一个瞬间落在另一段时间的中间，才算一人两地。画布和检查脚本都是这样算的。
- **谁知道什么要有来源**：`learns` 的 `from` 必填（亲眼看见、亲耳听见、谁告诉的、看到了什么东西）。一个人知道了他不可能知道的事，就是剧本漏洞。
- **看见、听见要说得通**：`perceives` 的人要么在同一个地点，要么在 `links` 里标了看得见、听得见的相邻地点。
- **误导线索要写清在哪被推翻**（`debunked`）。被排除的嫌疑人写 `clearedAt`。
- **真相不能漏进没标 `spoiler` 的文字**：比如节拍写“金社长溜回 302”，却没标 `spoiler`，画布在观众视角下就会把底泄了。
- **案子类型**：`whodunit` 要防止“太早暴露凶手”；`howcatch` 本来就让观众知道是谁，看点在怎么抓，不查这一条。
