# 真人模式：在 5090 上一场一场拍连续的真人戏

动态漫是“一镜一张图”；真人模式是“一场一条视频”：MiniMax-H3（开源版，跑在用户租的 5090 上的 ComfyUI）一次生成 4–15 秒，**里面可以有 2–4 个镜头、多句对白，画面、口型、声音、环境声一起出来**，人是真的在演。

**开机、关机**：5090 是 AutoDL 的容器实例 Pro（编号 pro- 开头）。`uv run ~/.claude/skills/manju/scripts/autodl.py status|balance|on|off`：on 会等到 ComfyUI 能用，off 会等到真的关了。开机按量花钱，每次开之前先告诉用户要做什么、大约多久，他同意了再开。AutoDL 的 5090 常常抢不到（2026-10-20 一晚上等了两个多小时）：拿到卡以后活干完也别关，留着等下一批，告诉用户机器还开着，他说关再关（空着每小时约 2.8 元）。开发者口令只放在 ~/.config/manju/autodl_token，用户自己存，不在聊天里传、不打印。

## 准备

- **远程 ComfyUI 地址**写在 `~/.config/manju/config.json`：`{"comfy_url": "https://xxx.seetacloud.com:8443"}`（或环境变量 `MJ_COMFY_URL`）。`uv run scripts/comfy.py status` 看显卡和队列。
- 这个地址公网可访问、没有登录，不要外传。服务器的 SSH 密码不需要，也不要用：所有操作走 ComfyUI 的接口。
- 服务器换了、模型目录变了也没关系：提交时会按文件名自动找到模型（比如自动加上 `minimax/` 前缀）。

## 最重要的一条：除了台词，提示词全部写英文

H3 会把提示词里的**中文**当成台词念出来（实测：它把角色设定“二十岁的中国女大学生……”整段念了出来）。所以真人模式里人物、场景、道具、镜头、动作、场景概要都写英文字段（`name_en`、`lock_en`、`camera_en`、`action_en`、`summary_en`、`sound_en`），只有台词在 `<d>[语言] …</d>` 里用要说的语言。`check` 和 `live` 会拦住还没写英文的地方。中文字段照样留着给人看、给 Codex 出定妆照用。

## 台词语言和字幕

- `live_lang`：台词用什么语言说，`Chinese`（默认）、`Korean`、`Japanese`、`English`。
- 每句台词 `text` 是演员说的话（比如韩语），`sub` 是字幕（比如中文）。字幕按 whisper 听到的时间出现。一句里有好几句话时拆成几条（同一个人连着写），字幕才会一句一句跟着嘴出，不会一屏三行。whisper 听岔了某句（字幕明显晚了），在那句台词里写 `"at": 场内开口的秒数` 手动钉住，开口时间用响度曲线看。

```json
{ "who": "su", "text": "망했다… 또 우산 안 가져왔네.", "sub": "完了，又没带伞。", "emotion": "悲伤" }
```

## 声线：用 Qwen3-TTS“设计”声音

edge-tts 读出来的参考声音很生硬，演员学了也难听。5090 上有 Qwen3-TTS，可以用一句英文描述“设计”一个声音（支持中英日韩等 10 种语言）：

```json
"su": {
  "voice_design": "A gentle, soft young Korean woman around twenty, clear and slightly breathy voice, warm and innocent, speaking quietly like a natural K-drama heroine.",
  "voice_sample": "비가 정말 많이 오네요. 오늘은 우산을 꼭 챙기려고 했는데, 또 깜빡했어요."
}
```

`mj voices` 有 `voice_design` 就在 5090 上生成（第一次会下载模型），`voice_sample` 是让她念的一段 6–10 秒的话，用台词语言写。有真人录音就用 `voice_ref`，优先级最高。

## 旁白和内心独白

旁白交代前情和世界观；内心独白说出人物不能说出口的话。不设配额，按剧情节奏用，画面和对白能演的就演。VO 单独用 Qwen3-TTS 配音，无须对口型，不占 5090 的 H3 拍摄时间；TTS 本身仍会使用远程 GPU。

`分镜.json` 顶层可写 `narrator`，每场用 `vo` 数组列出配音：

```json
{
  "narrator": {
    "name": "旁白",
    "voice_design": "A calm, deep, slightly husky Chinese male storyteller voice, unhurried, like a historical drama narrator.",
    "voice_sample": "世人都说，诡道沈夜死有余辜。"
  },
  "segments": [
    {
      "id": 1,
      "vo": [
        {"who": "narrator", "text": "世人都说，诡道沈夜死有余辜。", "at": 0.3, "kind": "narration"}
      ]
    },
    {
      "id": 4,
      "vo": [
        {"who": "shen", "text": "十三年……你就是这么过的？", "at": 8.0, "kind": "inner"}
      ]
    }
  ]
}
```

以上只展示新增字段，场内原有的 `seconds`、`shots` 等照常保留。

| 字段 | 说明 |
|---|---|
| `narrator.name` | 旁白的显示名称 |
| `narrator.voice_design` | 英文声音描述，`who: narrator` 用此描述设计声线 |
| `narrator.voice_sample` | 声线示例文本；生成旁白时直接朗读每句 `vo.text` |
| `vo.who` | `narrator` 或角色 id；角色用 `assets/声音/<id>.wav` 克隆，参考原文取角色的 `voice_sample`，须与参考音一致 |
| `vo.text` / `vo.sub` | 要念的文本；可选 `sub` 为翻译字幕，默认显示 `text` |
| `vo.at` | 相对于该场 `keep` 剪好、`video_in` 去掉之后的秒数，必须非负；成片含封面时整体再后移封面时长 |
| `vo.kind` | `narration` 为暖灰金色字 `(232,220,190)`；`inner` 为淡白字 `(225,225,225)`，字幕自动加全角括号 `（）` |

```sh
mj voices <集目录>                  # 先准备人物参考声线
mj vo <集目录>                      # audio/vo_seg01_1.wav …，已有的跳过
mj vo <集目录> --segments 2,3 --force # 仅重新生成指定场的 VO
mj check <集目录>                   # 统计各场句数，检查配音是否超出剪后场长
mj assemble <集目录>
```

VO 按“场开始时间 + at”叠加，统一到本集对白的响度（没有可测对白时用 -18 LUFS）。播放期间本场原声平滑压到 50%，配乐和环境音也按说话时间压低。字幕放在对白位置，重叠时移到对白上方；SRT 同时包含对白和 VO，颜色保存在烧录字幕中。

VO 不会自动延长场长。超出场尾时 `check` 和 `assemble` 会警告，合成会截断超出部分；应提前 `at`、缩短文本或调整剪辑。改了文本或声线后用 `--force`，缓存文件按场号和句序号识别。

## 分镜.json 怎么写

顶层加 `"mode": "live"`，镜头不写在 `shots`，写在 `segments`（场）：

```json
{
  "mode": "live",
  "style": "真人实拍的短剧画面，写实电影质感……（出定妆照用，中文）",
  "live_style": "Realistic live-action Chinese short drama, cinematic film look……（拍视频用，英文效果更稳）",
  "live_size": "480x864",
  "live_steps": 25,
  "live_sound": "Heavy rain……No background music.",
  "characters": { "su": { "name": "苏晚", "lock": "……", "voice": "zh-CN-XiaoxiaoNeural", "voice_emotion": "温柔" } },
  "scenes": { "store": { "name": "……", "lock": "……" } },
  "props": { "umbrella": { "name": "黑伞", "lock": "……", "text": "伞柄上刻着“苏晚”两个汉字" } },
  "segments": [
    {
      "id": 1, "seconds": 12, "scene": "store", "characters": ["su", "lu"], "props": [],
      "caption": "晚上十点 · 暴雨",
      "summary": "这一场讲什么（一句话）",
      "continue": false,
      "shots": [
        { "camera": "全景，镜头缓慢推近", "action": "苏晚……叹了口气。", "lines": [{ "who": "su", "text": "完了，又没带伞。", "emotion": "悲伤" }] },
        { "camera": "中景，固定机位", "action": "……陆沉……走出来，在她身边停下。", "lines": [] }
      ]
    }
  ]
}
```

| 场的字段 | 说明 |
|---|---|
| `seconds` | 4–15 秒（H3 一次最长约 15 秒）。中文台词每秒约 4 个字，再给每句留 0.6 秒；韩语按每秒约 5.5 个音节、每句留 0.4 秒算（第一版实拍量的：H3 念韩语中位 5.8 音节/秒，四分位 4.9–6.3），`check` 按 `live_lang` 自动选；都再留 1 秒给动作 |
| `characters` / `scene` / `props` | 这一场出现的人、地点、道具；对应的定妆照、场景图、道具图自动当参考图（最多 9 张） |
| `shots` | 这一场里的镜头，2–4 个最稳。`action` 里直接写角色名字，会自动换成 `<Subject n>（名字）`。镜头可以写 `"seconds"`：写了就给它这么长，没写的镜头按台词多少分剩下的时间。没台词、但要做完一个动作的镜头（进门、跑走、扯下东西）记得写 2.5–4 秒，不然按字数只能分到一秒多 |
| `lines` | 台词，生成时写成 `<d>[Chinese] ……</d>`，模型自己念、自己对口型 |
| `continue` | true：上一场最后一帧当参考图（弱接续）；false（默认）：场与场之间硬切 |
| `extend` | true：把上一场最后 22 帧画面和声音钉在这一场开头接着拍（你的 H3-B 接续做法，接在多角色参考后面，人物和声线不丢），生成后自动去掉重叠的 0.92 秒。同一时刻、同一地点连着发生的戏用它 |
| `keyframes` | `[{"image": "assets/xx.png", "at": 0}]`：在第 at 秒钉一张画面（H3-A 关键帧做法），比如开头必须是“闭着眼”的样子。图用 Codex 按定妆照出 |
| `from` | `[[0, 3.2, "videos/seg17.mp4"], …]`：这一场不单独拍，从别的场剪几段拼起来（比如冷开场直接用后面高潮的片段），`live` 会跳过它 |
| `drive` | true：先配音后对口型。用角色定好的声音（Qwen3 克隆）把这一场的台词念好，锁进 H3（`VRGDG_MiniMaxH3AudioDrive`），画面照着它对嘴，成片里的声音就是这条。顶层 `"drive_audio": true` 对所有有台词的场生效，某场写 `"drive": false` 关掉（尖叫、喘气这类克隆念不好的）。可以几个人对话：每句用说话人自己的声音，按顺序排成一条音轨，提示词里按开口顺序标 (S1)/(S2)，并写清每句的真实起止时间（官方 ref 指南写法）。台词之间的停顿用每句的 `pause`（秒，默认 0.35） |
| `refs` | 额外参考图（`shot03` 或图片路径） |
| `seed` | 固定这一场的种子，换种子重拍得到不同的表演 |
| `sound` | 这一场的环境声描述，不写就用 `live_sound` |
| `video_in`、`volume` | 合成时跳过开头几秒、这一场原声的音量 |
| `cards` | 后期字卡：`[{"kind": "time", "text": "02:00:45", "at": 0.3, "seconds": 2.5}]`。`time` 是右上角的小时间牌，`place` 是上方居中的地名卡，`name` 是左下的人物字卡（写成"名字｜身份"）。`at` 是这一场里的秒数。现代剧用它，`caption`（只能在开头居中停 3 秒）和古风的 `intros` 留给别的题材 |
| `inserts` | 后期整屏贴图：`[{"id": "ep01_s02_a", "at": 3.0, "seconds": 2.5, "desc": "手机屏幕上是中介发来的消息……", "text": "图里真出现的字（韩文照原样）", "sub": "中文翻译"}]`。`text` 只写画进图里的字，别夹中文；`sub` 合成时当字幕跟贴图同进同出，有人说话就挪到对白上方。手机屏幕、名片、帖子这类要写韩文、画界面的画面，视频模型画不准，用 `mj inserts` 按 `desc`、`text` 让 Codex 出一张竖图（`inserts/<id>.png`），合成时整屏盖上去，声音照常走。拍的时候这一段让人物低头看手机就行 |
| `inserts` 里的手机界面 | 聊天、邮件、帖子、锁屏通知、来电、视频播放页这类**手机界面**，不要让 Codex 画成一张张静态图（几张图接着贴会一闪一闪，界面也假）。在 `inserts/ui.json` 里写每个屏幕（`type`: chat / mail / post / notifications / call / views；韩文 `ko` 配中文 `zh`；chat 每条消息写 `at` 几秒弹出、可选 `typing` 先显示正在输入；旧消息 `at` 写 null 开场就在），`phone_ui.py inserts/ui.json inserts/ui` 出 1080×1920 的动画小片（气泡一条条弹出、翻译在每条下面、计数器会涨）。分镜里写成 `{"id": ..., "video": "inserts/ui/<id>.mp4", "video_in": 0, "at": ..., "seconds": ..., "look": false}`：`look: false` 不加颗粒暗角，才像真手机；不要再写 `sub`，中文已经在界面里。同一个聊天窗口来了几条，就做成一段，不要拆成几张。消息弹出的时刻配 `msg_ping` 音效。名片、标签这种实物特写还是用 Codex 出图 |

一场最多 3 个人说话（参考声音最多 3 段）。

### 同一个人换装
- 剧情要换衣服（睡衣、戏服、贴面膜），就另起一个角色 id，比如 `bride_pj`，lock 里写“就是新娘本人”加新衣服，`refs` 挂原来的定妆照，再写 `"voice_of": "bride"`：声音、voice_sample 都用原角色的，`mj voices` 会跳过它。
- 一场里同一个人只挂一个造型。两个造型同时挂上，模型会画出两个人；中途换装（比如拍上面膜）用文字写在动作里。

### 一个案子几集共用一套素材
- 第 1 集的 `分镜.json` 写全人物、场景、道具（和声音）；第 2 集起只写 `"episode"`、`"assets_from": "../EP01/分镜.json"` 和自己的 `segments`。人物、场景、道具会合并进来（这一集写了同名的就用这一集的），风格这些顶层设置没写的也照第 1 集。定妆照、场景图、参考声音都去第 1 集的 `assets` 里找。
- 设定图可以带参考图：人物、场景、道具里写 `"refs": [{"path": "assets/场景/minbak.png", "label": "同一栋楼的白天，照它"}]`。夜景、近景照着已经定好的外景出，楼、门、楼梯才对得上。要写字的场景（门牌、标签）写 `"text"`。

## 流程

```
mj check   <集目录>        检查场的时长、台词放不放得下、说话人数
mj sheets  <集目录>        Codex 出真人定妆照、场景图、道具图（免费，style 写成写实）
mj voices  <集目录>        每个角色一段参考声音（edge-tts 读他自己的台词；有真人录音就写 voice_ref）
mj inserts <集目录>        有 inserts 的话，Codex 出整屏贴图（免费）；只重出几张：--only ep01_s02_a,ep01_s02_b --force。同一个聊天窗口出好几张时，后面几张的 refs 挂第一张，界面才一样
phone_ui.py inserts/ui.json inserts/ui   手机界面动画（本机，免费，十几秒出完）；用 mj 的 uv 环境里的 python 跑（要 Pillow、numpy）
mj live    <集目录>        一场一场提交到 5090，videos/seg01.mp4 …（--segments 2 --force 只重拍第 2 场）
mj ambience <集目录> rain   可选：再垫一层环境音
mj assemble <集目录>       接起来：用每场自己的声音，whisper 听出每句台词的时间放字幕，调色、角标、响度
mj qc      <集目录>        自检（台词都识别得出来才算过）
```

每场的提示词存在 `build/seg01.prompt.json`，不满意先看它。

## 速度和画质（RTX 5090 实测）

- 480×864、25 步、10 秒：生成约 3.5 分钟（不算排队）。一集 4 场约 15 分钟。
- 720×1280、25 步、加真人 LoRA（《海声民宿》2026-10-20 实测）：13 秒的场 18 分钟，15 秒的场 19 分钟，12 秒的场 13 分钟，大约每 1 秒成片要 70–80 秒。一集 157 秒约 3 个多小时，AutoDL 5090 约 2.8 元/小时。开拍前按这个给用户报时间和钱。
- 想更清楚：`live_size` 改成 `576x1024` 或 `720x1280`，时间大约成倍增加。合成时会放大到 1080×1920。
- **高清修复（2026-10-27 实测，推荐）**：H3 出的 720×1280 放大到 1080×1920 后头发、睫毛是糊的，后期锐化没用。服务器上已装 SeedVR2（numz 节点 `SeedVR2VideoUpscaler`，模型 `seedvr2_ema_7b_sharp_fp16.safetensors`、VAE `ema_vae_fp16.safetensors`），`resolution` 1080、`batch_size` 33、`temporal_overlap` 4、`color_correction` lab、VAE `decode_tiled`，用 `VHS_LoadVideo` 读、`VHS_VideoCombine` crf 14 存，带原声。10 秒一条约 7 分钟（含加载模型）。睫毛、眼皮褶、皮肤纹理、发丝都出来了，人脸没变，前后帧没有明显闪。普通 7B 和 7B sharp 差不多，sharp 稍锐。服务器上还有 FlashVSR 和 H3 自己的潜空间放大（`h3_upscaler_*`、`minimax_h3_latent_upscaler_3d_*`），没试过。
- **高清修复后去斑（2026-10-27 用户反馈“脸上好多斑点”）**：SeedVR2 会把 720 原片里很淡的痘印、斑点放大成清楚的黑点，脸占画面越大越明显（床上自拍那种近脸）；普通 7B 和 sharp 都会。本机免费处理：`uv run --with opencv-python-headless --with numpy ~/.claude/skills/manju/scripts/skin_clean.py 输入.mp4 输出.mp4 --t1 18 --t2 45 --keep 0.12 --sigma 8`，只压皮肤色区域里中等大小、对比不强的暗点，眉毛、睫毛、发丝、嘴唇、猫毛都保留，10 秒一条约 20 秒。先用 `--frame 秒 --png 对比.png` 出一帧左右对比看效果再跑整条。脸干净的场次不用跑。只去比周围暗的点，高光保留（第一版连高光一起压，用户说“脸上好暗”）。
- **脸偏暗就提亮（2026-10-27）**：H3 拍的侧逆光，脸亮度常在 100 左右（满分 255），手机自拍一般 120–140，用户会觉得“脸暗”。`skin_clean.py` 加 `--lift 1.1–1.3`（中间调提亮，黑白两端不动），不去斑只提亮用 `--keep 1`。先量每场脸的平均亮度（ffmpeg `signalstats` 的 YAVG），把各场拉到差不多。
- 想更快：服务器上有 H3 Ref2VA 的 4 步/8 步加速 LoRA（`minimax_h3_ref2v_turbo_*`），画质换速度，后续可以加开关。

## 拍得好的经验

- **一段 10 秒左右，一集 9–10 段**：别拆成 4–5 秒的碎段。每段都要单独排队、单独起步，碎段一多总时间反而更长（《民宿有鬼》第 1 集 25 段拍了 3 个多小时），段与段之间接不上的穿帮也更多。一段里放 2–3 个镜头，可以两个人对话，景别有远有近；同一时刻同一地点连着的戏用 `extend` 接。用户 2026-10 看完第 1 集后明确要回到 10 秒一段。
- **拍之前对一遍“上一段结尾 → 下一段开头”**：人站着还是坐着、躺在哪、手里拿什么、枕头在哪、门是什么颜色、天色是白天黄昏还是夜里，每一段的描述里写死。模型会自己加切镜头、换背景、换天色（第 1 集：天台的门从棕色变蓝色、夕阳变白天；倒地的人下一段消失；码头背景突然出现在马路上）。同一个地方不同天色要各有一张场景图，门口、屋里这些近景也要先出图。
- **一个镜头一个动作**，复杂动作（推人、摔倒、翻越）拆到不同镜头或不同场。
- **台词别塞满**：一场 10 秒放 2–3 句。说得太赶模型会吞字。
- **参考声音决定声线**：edge-tts 读的够用；要更像真人，用真人录一段 6–10 秒、情绪平稳的话，写到角色的 `voice_ref`。
- **防穿帮要写死**：同一个道具只有一个时写明 “There is only one umbrella in the scene, and X is holding it”；谁留在原地、谁走开也要写明（“She does not follow him”），不然模型会让两个人一起走。
- **别留空镜**：每个镜头都写清楚画面里有谁（“both in frame”），不然会出现一两秒没人的画面。
- **画面里的字**（伞柄刻字）视频模型不一定写得对，靠道具图 + 特写，出来后检查，不对就换种子重拍那一场。
- **悬念要写死**：某个人这一场只露背影（脸留到下一场揭晓），每个镜头都写 “seen only from behind, his face is not visible at all”，场景概要也写一遍。模型手里有他的定妆照，不写就会把正脸拍出来，悬念就没了。
- **手的特写写清袖子颜色**：只拍手的镜头里模型不知道是谁的手，常把袖子换成另一个角色的颜色（白衣人的手配了黑袖子）。写 “X's hand in a WHITE linen sleeve … The sleeve is white, not black.”，两人握手时分别写清谁的袖子什么颜色。
- **含泪的笑要写克制**：只写 smiles 会笑成露齿大笑；写 “a small trembling smile with closed lips, eyes red and wet, not a grin”。
- **LoRA 触发词不进提示词**：H3 会把 `r34l1sm` 这类词当台词念出来（第 2 集实测，成片里多出一句“234 LLSM”）。`live_loras` 里的 `trigger` 默认只做记录，确实要写进提示词时加 `"trigger_in_prompt": true`，拍完用 Demucs 分出人声检查。
- **钉画面的场宽高要是 32 的倍数**：`extend` / `keyframes` 在 720×1280 下会报 `shape ... is invalid`，`live` 会自动把这一场改成 704×1280。
- **外貌里别写“干裂的嘴唇”这类词**：角色设定写了 chapped lips + 红色眼妆，H3 让他张嘴笑时嘴角会流血（第 2 集两场都这样）。H3 没有反向提示词，写 “no blood” 反而把 blood 塞进了提示词；改外貌描述、让他闭着嘴笑才有用。
- **晴天戏要换晴天的场景图**：参考图是阴天，提示词写 sunlight 也拍不出阳光；用 Codex 按原场景图出一张晴天版。
- **硬切比强行接续更稳**：只有同一地点、同一时刻继续的戏才用 `continue`。
- **两个人对话：口型要分得清是谁**（2026-10-14 起允许一段里两人对话，用户嫌“一段只一个人说”太限制；开 drive 时按 S1/S2 和每句时间写提示词，开机后先拿 2–3 条 6 秒的小样验证口型落点再大批拍）：同一镜头里两个人轮流说，或者说话的人背对镜头，H3 常把台词对到另一个人嘴上（第 2 集“它只会答‘是’”“是你吗”都对到了沈夜嘴上）。稳妥的拍法：正反打（说话的人在画面里、脸朝镜头，另一个人的台词放到下一个镜头），或者斜着站的双人镜头里说话的人脸朝镜头、听的人侧脸。不要一直怼脸：双人中景、全景交代站位，近景和特写留给反应和揭晓。必须背对时，这句改成画外音（另一个人的特写里听见），或者后期配。
- **道具的状态每个镜头写清楚**：碗是空的还是盛着粥、灯亮没亮、门开没开。只写“他接过碗”，下一镜可能就从空碗变成在喝粥。写 “the bowl is now filled with white porridge” 这样的状态句，前后镜头对得上。
- **画面要亮、脸要看得清**：竖屏短剧在手机上看，暗部再“电影感”也只是一片黑。风格里写柔和的主光打在脸上（soft key light on the faces, faces clearly lit），不要写 deep shadows / only candlelight；后期 `grade` 不要再压暗。夜戏也要让脸亮。
- **场景要符合设定，别画得太新太豪华**：Codex 默认把房子画成新装修、网红风。设定里是“开了三十年、快开不下去的老民宿”，就要写清楚旧在哪里（掉漆、裂缝、旧墙纸、地板革、塑料拖鞋），有几层、每一层都要看得见，以及“不豪华、不是精品酒店”。
- **先把房子的格局定死，再出图**：几层、每层几间、房号、谁住哪间、人从哪里进出（正门、侧楼梯、天台怎么上去），写进大纲。外景图要数得对：每层窗户数等于房间数，楼梯和天台小屋看得出怎么走上去。剧情里的走位（谁从哪扇门出来、谁在哪儿能拍到谁）都要在这个格局里走得通。每个常驻人物的屋子都单独出一张图：房型统一，屋里的东西看得出是谁住的。
- **场景要符合设定，新旧要拿捏好**：Codex 默认把房子画成新装修、网红风；可一写“老旧”，又容易画成破楼。按人物的处境写到中间那一档，比如“开了三十年、被外婆照顾得很好的家庭民宿：有年代感但整洁温馨，像外婆家；不是新楼，不是精品酒店，也不破旧”。楼有几层，每一层都要看得见。
- **每个人的肤色和瑕疵要不一样**：不写的话，Codex 和 H3 会把所有人画成同一种白净光滑的脸，一看就是 AI。按人物的生活写进外貌：晒黑的渔民、熬夜的暗黄脸、红脸膛、雀斑、痘、痘印、痣、晒脱皮、老年斑、眼镜、招风耳。用户 2026-10 看《民宿有鬼》定妆照时专门指出过。
- **妆容别写成“诡异”**：苍白皮肤 + 暗红烟熏眼妆 + 暗调，看起来像鬼。古装剧用正常的淡妆，人物的特点放在发型、服装、道具上。
- **声音要稳就先配音后拍（`drive_audio`）**：模型现场生成的声音每场都不一样，拍完再换声音（`mj redub`）又很难卡准嘴型（模型会把“哎哟~”拖长，新念的说得干脆）。先让用户从 2–3 个 Qwen3 候选里挑定每个人的声音，再开 `drive_audio`，台词念好锁进去拍：声音就是选定的那个，嘴照着它动（《民宿有鬼》第 1 集实测）。`redub` 留着给已经拍好、不想重拍的场救急。
- **同一个人的声音会一场一个样**：每场的声音都是模型现场生成，参考声音只能拉近，不能锁死。主角的参考声音要设计得特点鲜明（男性写清 low, deep, masculine，避免 breathy、soft 这类词，否则容易偏女气）；拍完逐场听，差得远的那几句用 Demucs 分出人声，再用 Qwen3-TTS 按参考声音克隆重配，盖回原位（第 1 集“你怎么还在弹这首”就是这样修的）。
- **电流声**：H3 生成的原声有时带一条持续的高频啸叫（第 2 集第 5、10、11 场在 4.5–5 kHz）。`qc` 会查出来；那一场加 `"denoise": true`，合成时降噪。

## 拍完逐场检查（每一场都要过）

模型交回来的每一场，看完这几项再往下走，不合格就换种子重拍那一场，或者用 `keep` 剪掉坏的几秒：

1. **说话的是谁**：抽出每句台词中间的一帧，看张嘴的是不是那个人（`qc` 会出 `out/对口型检查.jpg`）。
2. **台本外的声音**：whisper 听一遍，台词以外不能有人声（触发词、乱念的提示词）。
3. **道具和动作的前后**：上一镜和下一镜里，碗、灯、门、衣服、谁站在哪，能不能接上。
4. **脸和妆**：有没有变脸、流血、多出来的手、奇怪的条纹。
5. **亮度**：在手机上看脸清不清楚。
6. **这一场讲没讲清楚**：静音看一遍，只看画面，能不能说出这一场发生了什么。说不出来，是剧本或分镜的问题，回去改，不要指望剪辑救。
